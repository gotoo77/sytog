# V0.2 — Local network session

## Scope

V0.2 connects multiple processes over WebSocket while keeping `sytog-domain`
and `sytog-runtime` transport-independent. The host is the sole logical
authority, sequencer, and producer of the canonical journal.

```text
clients
  │ Envelope V0 / WebSocket
  ▼
sytog-transport
  ▼
sytog-node
  ├── decision through sytog-runtime
  ├── durable JSONL journal
  └── accepted-event broadcast
```

`sytog-node` receives an `ActivityEngine` and does not depend on any concrete
activity. The CLI injects `demo.vote` and parses its interactive commands.

## Messages

Every `Envelope` contains one typed payload:

- `Hello`;
- `JoinSession`;
- `SubmitCommand`;
- `CommandRejected`;
- `EventBatch`;
- `StateSnapshot`;
- `CatchUpRequest`.

Commands carry `message_id` and `expected_revision`. Broadcast facts carry
`event_id`, `causation_id`, and `sequence`.

## Acceptance order

While holding the canonical session lock, the host:

1. decides without mutating canonical state;
2. applies the decision to a copy;
3. validates the prospective journal;
4. appends events to `events.jsonl` and synchronizes the file;
5. replaces canonical state;
6. refreshes the derived snapshot;
7. broadcasts the accepted batch.

A persistence failure prevents both the in-memory commit and broadcast. The
snapshot is a rebuildable projection: a failure after the durable commit is
reported but does not falsely reject the command.

## Persistence

```text
data/
  sessions/<session-id>/
    metadata.json
    events.jsonl
    snapshot.json
  clients/
    <session-id>-<participant-id>.json
```

On restart, the host does not trust the snapshot as its source of authority: it
validates and replays the journal from revision zero. A reconnecting client
sends its last reduced sequence and receives only the missing suffix.

## Demonstration

```bash
cargo build -p sytog-cli
./target/debug/sytog serve --bind 127.0.0.1:7878
./target/debug/sytog connect ws://127.0.0.1:7878 --participant alice
./target/debug/sytog connect ws://127.0.0.1:7878 --participant bob
```

After both participants connect:

```text
alice> open tea coffee
bob>   vote coffee
alice> vote tea
alice> close
```

`state` must show the same state and revision in both clients.

## Explicit limitations

- one `demo.vote` session per host process;
- no application TLS or cryptographic identity;
- no LAN discovery, WebRTC, consensus, or multiple authorities;
- no journal compaction or automatic recovery of a partially written final
  JSONL line yet;
- `StateSnapshot` is defined for future negotiation, while V0.2 catch-up uses
  event batches.
