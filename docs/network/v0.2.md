# V0.2 — Session réseau locale

## Portée

La V0.2 relie plusieurs processus par WebSocket tout en conservant
`sytog-domain` et `sytog-runtime` indépendants du transport. L’hôte est
l’unique autorité logique, séquenceur et producteur du journal canonique.

```text
clients
  │ Envelope V0 / WebSocket
  ▼
sytog-transport
  ▼
sytog-node
  ├── décision via sytog-runtime
  ├── journal JSONL durable
  └── diffusion des événements acceptés
```

`sytog-node` reçoit un `ActivityEngine` et ne dépend d’aucune activité concrète.
La CLI injecte `demo.vote` et interprète ses commandes interactives.

## Messages

Le payload typé de chaque `Envelope` est l’un des messages suivants :

- `Hello` ;
- `JoinSession` ;
- `SubmitCommand` ;
- `CommandRejected` ;
- `EventBatch` ;
- `StateSnapshot` ;
- `CatchUpRequest`.

Les commandes portent `message_id` et `expected_revision`. Les faits diffusés
portent `event_id`, `causation_id` et `sequence`.

## Ordre d’acceptation

Sous le verrou de la session canonique, l’hôte :

1. décide sans modifier l’état canonique ;
2. applique la décision sur une copie ;
3. valide le journal prospectif ;
4. ajoute les événements à `events.jsonl` et synchronise le fichier ;
5. remplace l’état canonique ;
6. actualise le snapshot dérivé ;
7. diffuse le lot accepté.

Un échec de persistance empêche le commit mémoire et la diffusion. Le snapshot
est une projection reconstructible : son échec après commit durable est signalé
mais ne rend pas la commande faussement refusée.

## Persistance

```text
data/
  sessions/<session-id>/
    metadata.json
    events.jsonl
    snapshot.json
  clients/
    <session-id>-<participant-id>.json
```

Au redémarrage, l’hôte ignore le snapshot comme source d’autorité et rejoue le
journal validé depuis la révision zéro. Un client en reconnexion envoie sa
dernière séquence réduite et reçoit uniquement le suffixe manquant.

## Démonstration

```bash
cargo build -p sytog-cli
./target/debug/sytog serve --bind 127.0.0.1:7878
./target/debug/sytog connect ws://127.0.0.1:7878 --participant alice
./target/debug/sytog connect ws://127.0.0.1:7878 --participant bob
```

Après connexion des deux participants :

```text
alice> open tea coffee
bob>   vote coffee
alice> vote tea
alice> close
```

`state` doit afficher le même état et la même révision dans les deux clients.

## Limites explicites

- une session `demo.vote` par processus hôte ;
- pas de TLS applicatif ni d’identité cryptographique ;
- pas de découverte LAN, WebRTC, consensus ou multi-autorité ;
- pas encore de compaction du journal ni de récupération automatique d’une
  dernière ligne JSONL partiellement écrite ;
- `StateSnapshot` est défini pour la négociation future, tandis que le rattrapage
  V0.2 utilise les lots d’événements.
