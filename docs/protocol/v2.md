# Protocol V2 — Overload and paged catch-up vocabulary

Status: vocabulary implemented; node behavior not enabled

Protocol V2 uses the existing JSON `Envelope` with `family = "sytog"` and
`version = 2`. V1 remains readable and retains its original typed payloads.
Version-specific decoding selects `NetworkMessage` for V1 and
`NetworkMessageV2` for V2. A V1 decoder rejects V2 and a V2 decoder rejects V1;
neither version reinterprets the other.

The existing host and client continue to emit and handle V1 only. V2 currently
defines contract vocabulary and validation; it does not enable queues,
timeouts, quotas, paged catch-up, snapshots, retention, or compaction.
`LATEST_PROTOCOL_VERSION` is therefore `2`, while
`ACTIVE_SERVER_PROTOCOL_VERSION` remains explicitly `1`.

## V2 messages

- `hello` declares `last_applied_sequence`, the highest contiguous sequence
  applied and persisted locally by the client;
- `join_session` and `submit_command` retain their V1 domain meaning;
- `command_rejected` reports an ordinary command rejection;
- `admission_rejected` reports work rejected before authoritative admission;
- `event_batch` carries a validated contiguous live range;
- `catch_up_request` requests facts after a durable client cursor;
- `catch_up_page` carries bounded-page metadata and a contiguous event range;
- `resync_required` ends continuous live delivery and requires reconnect;
- `state_snapshot` remains vocabulary only and is not operational.

## Stable reasons

Established-connection resynchronization reasons:

| Name | Numeric code |
|---|---:|
| `outbound_queue_full` | 4101 |
| `outbound_byte_budget_exceeded` | 4102 |
| `write_timeout` | 4103 |
| `catch_up_limit_exceeded` | 4104 |
| `cursor_before_retention` | 4105 |

Pre-admission rejection is a distinct message and reason:

| Name | Numeric code |
|---|---:|
| `server_overloaded` | 4201 |

An established connection requiring resynchronization uses WebSocket close
code `4001` and short reason `resync_required`. Delivery of a final
`resync_required` message or close frame is necessarily best effort. Any
transport close therefore requires the client to reconnect from its own durable
applied cursor.

## Catch-up page metadata

Every non-empty `catch_up_page` contains:

- `earliest_available_sequence`;
- `from_sequence`;
- `through_sequence`;
- `current_sequence`, the captured catch-up high-water mark;
- optional `snapshot_revision`;
- `terminal`, true exactly when `through_sequence == current_sequence`;
- the page events.

Validation rejects:

- empty pages or sequence zero;
- inverted ranges;
- an earliest available sequence after the page start;
- a page ending after the current high-water mark;
- contradictory `terminal` values;
- non-contiguous events or mismatched range bounds;
- a snapshot revision not immediately preceding its first suffix page;
- resync metadata whose snapshot cannot bridge to retained data.

No numeric page-size, byte, duration, connection, or concurrency limit is fixed
in this protocol slice.

## Compatibility fixtures

- `fixtures/protocol/envelope-v1.json` remains the V1 envelope contract;
- `fixtures/protocol/envelope-v2-resync-required.json` fixes V2 message and
  reason names.

Unknown protocol versions remain explicit errors.
